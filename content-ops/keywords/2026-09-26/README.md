# Keyword batches, 2026-09-26

Generated by `npm run keywords -- expand` from 1,159 unbriefed English chapters and
5,161 unpublished catalogue questions, giving 23,590 unique keywords in ten batches.

## To do in Ahrefs

1. Keywords Explorer → search engine **Google**, country **United States**.
2. Paste `batch-01.txt` and run it.
3. Export the overview as CSV into this folder. Either encoding works (UTF-16 or
   UTF-8), and the file name doesn't matter.
4. Repeat for `batch-02.txt` through `batch-10.txt`.

Each batch holds 2,500 keywords, the number of rows a Keywords Explorer report
shows on Ahrefs Lite. A bigger paste on Lite exports only its first 2,500 rows. On
Standard or above (30,000 rows a report), `npm run keywords -- expand --batch 10000`
gives three pastes instead. It writes a folder dated the day it runs, with its own
`keywords.csv`, so export into that folder and score that one.

Then run `npm run keywords -- score content-ops/keywords/2026-09-26`. It prints how
many of each batch's keywords the exports cover, so a batch that was skipped or
cut short shows up. It writes `scores-chapters.csv` and `scores-questions.csv`,
highest demand first.

## The other files

- `keywords.csv` maps every keyword back to the chapter or question it stands for,
  and records which form it is (`study`, `study-variant`, `bare`, `raw`,
  `shortened`, `phrase`, `verse`). `score` needs it, so keep it with the exports.
- `shortened-questions.csv` lists the 2,155 questions too long to look up as
  written, next to the form that was looked up instead. About 80 were checked by
  hand, along with the cases a code review raised (split references like "in 1 John
  3", quoted lines losing their last word). The rules in `scripts/keywords-lookup.mjs`
  were revised until the sampled forms read the way someone would type them.
